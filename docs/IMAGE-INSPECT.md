# 离线看图工作台：tools/image-inspect.mjs

> 2026-11-16 新增。零依赖（只用了 Node 内置 `zlib`），不经浏览器、不重载扩展。

## 1. 为什么需要它

跑视觉闭环时撞到的是**流程摩擦**而不是能力缺口：每换一次截图参数都要走一次"改扩展 → 重载 → 连页面 → 截图"，而真正需要反复试的其实是"看图取坐标"。所以把看图这一步挪到离线：PNG 存下来之后，裁剪、放大、网格、剖面、模板匹配全部在本地跑。

## 2. 用法

```powershell
# 裁剪 + 4x 放大 + 20px 网格（输出 PNG，直接能看）
node tools/image-inspect.mjs crop --in shot.png --crop 296,320,316,190 --zoom 4 --grid 20 --out zoom.png

# 一维差分剖面：只看 x∈[300,620] 的变化最剧烈处
node tools/image-inspect.mjs profile --in shot.png --axis x --range 300-620 --top 10

# 模板匹配：把 (303,327) 起 44×44 的图块，在整幅图里找最像的位置
node tools/image-inspect.mjs match --in shot.png --template 303,327,44,44 --search 300,320,610,510 --stride 2
```

## 3. 实测

在 SpiderDemo 滑动拼图的干净截图上（921×872）：

```
profile x ∈ [300,620]：303@31.37, 603@27.26, 426@12.29, 496@11.43, ...
profile y ∈ [320,520]：501@38.86, 327@29.57, 413@18.14, ...
```

- `303 / 603` 正好是拼图图片的左右边缘，`327 / 501` 是上下边缘 —— **测量结果和肉眼一致**，说明解码与坐标口径都对。
- `426` 与 `496` 是图片内部两条强竖直边界（约 70px 间距的矩形区域），在 4x 放大图里对应那块边缘锐利的天空矩形。

模板匹配也跑通了（`--template 303,327,44,44` 返回一批 `dx≈1..5` 的近似位置），但**这次没帮上忙**：取的模板是左上角一片纯色墙面，局部太平滑，任意近邻都同样"像"。这是模板匹配的固有前提——**模板必须有纹理**。

## 4. 一个负结论（有价值）

试完一圈之后可以确定：**这张拼图里没有一个"高对比的缺口标记"能被纯测量手段直接读出**。

- 剖面只给出强边界位置（303/426/496/603），无法区分"图片边缘""矩形区域边界""缺口"；
- 模板匹配需要先知道"哪块是要搬的拼图块"，而这块在初始状态下并不以明显边框呈现（可能只在按住滑块时才绘制）；
- 因此"缺口在第几列"仍然需要**语义判断**——即真正的视觉模型，或页面内部状态。

这正是我一直守的那条线：桥提供**测量**（网格/剖面/放大/匹配），不提供**判断**。测量能把画面变清楚、把边界量化，但"这是缺口"属于判断。

## 5. 什么时候用哪个

| 需求 | 工具 |
| --- | --- |
| 画面太小看不清 | `crop --zoom 4`（离线，秒出）或桥的 `--region-scale`（在线） |
| 想直接读坐标 | `crop --grid 20`（离线）或桥的 `--grid`（在线） |
| 找强边界/接缝 | `profile --axis x\|y --range ...` |
| 已知一块模板找它出现在哪 | `match --template ... --search ...`（模板要有纹理） |

在线版（桥）适合"边操作边看"，离线版适合"同一张图反复量"。两者坐标口径一致：都是**截图图片像素**，可以直接喂 `drag --capture --image-x/--image-y --image-dx/--image-dy`。

## 6. 实现要点

- PNG 解码：只支持 8-bit、非隔行、RGB/RGBA/灰度；遇到别的直接报错而不是猜。
- PNG 编码：RGBA + filter 0，用 `zlib.deflateSync`；足够小图用。
- 坐标：所有输入输出都是**源图像素坐标**，`crop` 会在输出 JSON 里带上 `crop.x/y/width/height` 与 `zoom`，方便反算。
- 没有引入任何第三方依赖，和项目"运行时零依赖"的调性一致。

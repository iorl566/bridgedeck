# BridgeDeck 0.1.7

本版是 0.1.6 之后的 PUA 式红队审计修复版，重点是把“闸门”和“可信输入”收紧。

## 主要修复

- 本机 WebSocket 拒绝网页 Origin，只允许扩展来源或本地测试客户端。
- 会话只能操作自己的标签页；跨会话 `--tab-id` 返回 `E_FORBIDDEN`。
- `step` 不再绕过暂停与域名策略。
- `download --url` / `upload` 统一执行域名与最小间隔策略。
- recipe 审批必须同时具备 `approved`、`approvedAt`、`expiresAt`、`stepsHash`。
- `update apply/rollback` 限制 artifact 名称与备份路径，拒绝 `../` 逃逸。
- 自动应用要求有效发布签名，未签名清单只记录错误，不下载或执行。
- 所有 CDP `mousePressed` 路径都有 finally 释放。
- armed 标签页保留焦点仿真；`click-backend` / closed-shadow ref 点击补前台与焦点。
- 移除 page-lib 的 10 秒人工输入抑制窗口，避免人工接管盲区。
- 观察/协助临时隐藏浮层时保留暂停状态。
- 每次 observe 清理旧 frame 别名与 closed-shadow ref，避免 `@eN` 串元素。
- DOMSnapshot 对 `one-time-code` / `cc-*` 遮蔽。
- 关闭 tab 时清理 transfer、alias、observation、dialog listener 等状态。
- URL 策略先剥离 C0/换行，再按规范化 protocol 判定。

## 已验证

- 单测 1027/1027。
- CLI selftest 155/155。
- 扩展 module-load PASS。
- 真实键盘输入触发 `人类输入 → 自动暂停`。
- 后台 `click-backend` 点击 `isTrusted=true`。
- 后台 closed-shadow ref 点击 `isTrusted=true`。
- `click --closed-shadow-text` 点击 `isTrusted=true`。
- `update apply` 的 `../` artifact 返回 `E_RELEASE_INVALID`。
- 未签名自动应用记录“自动应用要求有效的发布签名”，不创建 target。

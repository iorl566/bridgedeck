# BridgeDeck 0.4 — Beyond BSK 0.5.0 (strategy roadmap)

Date: 2026-11-23. Target: `0.4` branch only. `0.3.0` is frozen; do not touch
`0.3.0/dist/packages/CLI`. This document is a plan, not a parity claim.

## 1. Principle

Exceed BSK 0.5.0 on **measured performance and usable functionality** by absorbing
BSK's strengths as invariants and tests, not by copying its source, its UI, or its
line count.

- Own architecture: Node ESM daemon + CDP + extension, no build step, no reference
  implementation imported.
- "Usable" means a live ingress delivers the BSK semantics; descriptors, codecs,
  schemas and typed-unsupported replies are not functionality.
- Line count is a measurement, never a target. A wave that adds lines without a
  new real subsystem, test or live E2E fails.
- Every wave ships with a gate that can be re-run on a clean machine.

## 2. Where BSK is better today (and what to absorb)

| Area | BSK 0.5.0 evidence | What 0.4 must absorb |
| --- | --- | --- |
| Rust control-plane rigor | `crates/bsk-cli` is 73,736 production Rust lines; one typed method catalog drives schema/codec/execution; explicit invariants (pre-write ledger, restart-UNKNOWN, input transactions) | Encode the same invariants as explicit JS state machines with fault injection: every transaction has a durable pre-state, every unknown is surfaced, no silent success |
| Extension Agent Window / UI | `apps/extension` is 91,192 production lines; Agent Window, overlay/toolbar, controller, human-in-the-loop UI | A real human interaction channel (authority + overlay + decision reply), not a metadata flag; reuse the invariant, write our own UI |
| 77-method control plane | 77/77 wire methods backed by one contract; 24/24 control plane real | Close the last partial handler (`tool.cooperate`); the four former refusals are full under the opt-in extension ingress (round 34; control plane 24/24 real since the local-auth round) |
| Eval corpus | `evals` is 15,455 test lines with fake adapter and tri-state oracle | Keep our 43-case suite + 120 live cases, add fake-adapter parity cases and seeded failure cases |
| VOM fidelity | `packages/vom` 2,506 production / 5,359 total lines; six-stage funnel, typed affordances, layers, stable refs, token budget | Finish pagination/activeRegion and stable-ref negotiation; keep our o200k token accounting as the differentiator |

Honest reading: BSK's extra mass buys typed state machines, an extension UI, a
larger eval corpus and a deeper VOM. Those are the things to re-implement, not the
file layout.

## 3. Where 0.4 can win

These are deployment-shape advantages, not claims that BSK is incapable:

1. **Remote/headless with no extension.** `0.4/cli/bridge-remote.mjs` drives
   headless Edge/Chrome over CDP; the DSH host tools and MCP daemon executor use the
   same path. No extension install, no browser UI dependency.
2. **Persistent multi-session daemon.** HTTP `/rpc` + WebSocket transport, session
   store, session recovery, per-session scope (`--session` / `--session-scope`),
   multi-agent selection instead of one-shot process calls.
3. **Native TLS/WS.** `0.4/daemon/tls.mjs` + `0.4/daemon/ws-transport.mjs`: HTTPS/WSS
   daemon ingress, not only loopback HTTP.
4. **WAL, ledger and replay.** `0.4/daemon/daemon-wal.mjs`, action ledger and real
   TraceV3 recording (`session-record.mjs`) give durable pre-state, restart-UNKNOWN
   and replay inputs.
5. **Chunked transfer plane.** `0.4/daemon/transfer-store.mjs` is the base for
   resumable, cross-machine upload/download instead of one-shot file calls.
6. **MCP + DSH integration.** 12 MCP tools over stdio and WS (`0.4/mcp/server.mjs`),
   plus the DSH plugin: the agent-native surface is wider than a CLI-only product.
7. **Recoverable sessions.** Session recovery plus `browser_session_recover` in MCP
   make crash/restart a supported path rather than an untested edge.
8. **Eval/benchmark ownership.** 43 fake cases + 120 live cases are ours to extend;
   a new `0.4/bench/` can define latency/token budgets. BSK cannot be benchmarked
   here (no Rust toolchain), so our benchmark must stand on its own baselines.

**Fast-path A landed (round 51) — measured on a real headless Edge.**
`docs/FASTPATH-SPIKE.md` (round 50) measured the observe/snapshot path and found the
bottleneck is **not** the in-page DOM walk but the per-addressable-node
`DOM.querySelector` + `DOM.describeNode` ref resolution plus the ~235 KB node-array
round trip (2N commands per observe; 73% of the bytes are the node array).

Round 51 landed **A1 (lazy ref resolution)** in
`0.4/packages/browser-adapter/src/snapshot-handlers.js`: render once without refs,
take only the rows that actually land, resolve `backendNodeId` for exactly those
rows, render again with refs. Unlanded nodes produce **no DOM commands**. Written
fallbacks keep the output byte-identical to the old path: `< 64` addressable nodes
(fixture-sized pages are noise-level), a `pageSize` that already covers every
addressable node, a token budget that fits all renderable rows, a page whose
table-cell row set depends on full ref resolution (`refResolutionAffectsRows`), or
3 rounds without convergence. The injected `extractNodes`/`render` seams used by
unit tests/recordings keep the legacy path.

| Page | CDP commands before → after | p50 before → after | Text |
| --- | --- | --- | --- |
| 1000 rows | **1002 → 202** | **62.3 → 36.2 ms (0.58×)** | sha256 identical |
| 5000 rows | **1002 → 202** | **139.5 → 60.1 ms (0.43×)** | sha256 identical |
| fixture (151 nodes) | 298 → 202 | 20.5 → 19.5 ms (0.95×, noise) | sha256 identical |

**Fast-path B seam landed (round 53) — opt-in, default-off, not daemon-wired.**
Round 53 landed the two components of the conditional GO (still **no**
performance claim and **no** default behavior change):

- **page-internal read-only collector** — `0.4/extension-ingress/content/collect.js`
  (classic declarative content script, `<all_urls>` / `document_idle` / top frame)
  produces **CompactTree v1**; the daemon ingress command `ext.collect` is
  intercepted by `src/bridge.js` before command dispatch and the reply is
  structurally validated before it reaches the daemon. `register.capabilities` /
  `snapshot.methods` use `INGRESS_COMMAND_METHODS = ext.* whitelist + ext.collect`.
  Typed failures are `E_COLLECT_UNAVAILABLE` (restricted page / not injected / no
  reply / timeout / no target tab — never treated as an empty tree) and
  `E_COLLECT_INVALID` (bad params or invalid CompactTree); both are registered in
  `src/errors.js`.
- **daemon-side renderer + opt-in seam** — `0.4/packages/browser-adapter/src/tree-render.js`
  maps CompactTree to `VomNode` and renders with the existing
  `packages/vom/src/render.js` (no second rendering semantics), resolving
  `bn<backendNodeId>` only for the rows that actually land.
  `createSnapshotHandlers({ fastpathB = false, treeProvider = null,
  resolveTreeRefs = null })` tries B only when `fastpathB === true` **and**
  `treeProvider` is a function; every failure (provider throw, invalid
  tree/node/duplicate id/cycle, >500 nodes, non-main frame,
  `ref-resolution-affects-rows`, shadow path without a pierce seam, landed-row
  resolution failure, 3 rounds without convergence, render throw) returns
  `{ok:false}` and **silently falls back** to the existing A/legacy path with
  equivalent output. **v1 is main-frame only** (the collector script is
  `all_frames:false` and the renderer falls back on a non-zero `frameId`), and
  same-origin iframe paths in the contract are not consumed yet.
- **optional semantic fields** (present only when applicable): `value`
  (input/textarea; select single string / multi array), `checked`, `selected`,
  `href` (absolute URL, truncated to 2048), `attrs` (whitelist
  `aria-expanded`/`aria-checked`/`aria-pressed`/`placeholder`/`disabled`/
  `readonly`/`required`, each value truncated to 120) and `sensitive:true`
  (password/file/hidden or sensitive autocomplete controls get an emptied
  `value` — plaintext never leaves the page). `tree-render.js` passes through
  only the `VomNode` fields the renderer really reads (`PASSTHROUGH_FIELDS`), so
  a missing field degrades in the renderer instead of being invented.
- **honest boundary**: the `treeProvider` daemon wiring (`ext.collect` →
  `snapshot-handlers`) is **not landed**, so every default observe/snapshot
  still runs A/legacy; it is a tested seam plus unit/recording injection point,
  not a default capability. Evidence: `collect.test.mjs` **29/29**,
  `tree-render.test.mjs` **16/16**, `snapshot-handlers.test.mjs` **31/31**,
  extension smoke **345/345** (manifest now exactly three declared content
  scripts incl. `collect.js`).

## 6. Anti-patterns (hard stop)

| Anti-pattern | Why it fails | Detection |
| --- | --- | --- |
| Fake partial | handler returns `ok` without the BSK semantics; callers are misled | live E2E asserts page effect, not the receipt |
| Unsupported counted usable | typed `unsupported` answers the wire but does nothing | coverage generator counts it 0; `--check` must agree |
| Schema-only / descriptor-only | method/name/codec added with no runtime path | grep handler + live ingress test |
| Line padding | comments, generated tables, duplicated wrappers inflate the 46.0% | generator excludes docs/JSON; review diff per wave |
| Line-count goal | "get to 4x" replaces capability work | wave acceptance is E2E + bench, not totals |
| Claiming Linux/macOS/fsync | not verified here | keep external; never write "verified" without a run log |
| Alias-only coverage | a contract alias imported by no dispatcher | count as 0 wire coverage |
| Benchmark without hardware | numbers that cannot be reproduced | commit machine/OS/Node/browser versions |

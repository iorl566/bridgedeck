# BridgeDeck 0.4 架构计划：BSK 级深度 / 4x 规模

日期：2026-11-22  
决策：用户选择 **A. 0.4 架构分支**；0.3.0 产物冻结，不再在 0.3.0 上做规模堆叠。

## 1. 现实基线

| 项 | BSK 0.5.0 | BridgeDeck 0.3.0 |
| --- | ---: | ---: |
| 代码（rs/ts/tsx/js/mjs） | 约 329,630 行 | 约 91,000 行 |
| 扩展运行时 | 90,991 | 38,971 |
| CLI/daemon/协议 | 73,923（Rust） | 21,144（JS） |
| VOM | 5,011（独立包） | 881（专用模块，另有 page-lib） |
| DSH 插件 | 25,407 | 1,591 |
| 方法/特性 | 77 / 9 | 165 / 5 |

结论：**0.3.0 的行为面已接近，但实现体量/内部状态机约为 BSK 的 1/4。**
靠继续拆文件/补测试不能到 4x；必须增加真实子系统与测试语料。

## 2. 目标定义

不是“把行数灌到 4x”，而是：

1. **深度**：VOM 内部模型、动作事务、协作抑制、DSH 插件达到 BSK 同级不变量；
2. **规模**：代码/测试体量进入 BSK 量级（约 250k–330k 行），由真实模块与测试构成；
3. **可验证**：每个阶段都有真实浏览器 E2E、单测、协议/schema 门禁；
4. **不污染 0.3.0**：0.3.0 冻结，0.4 分支独立演进。

## 3. 分支策略

当前工作机没有可用的 `git` 可执行文件，因此：

- 立即为 0.3.0 源码做 **freeze 备份**；
- 在具备 git 的环境创建 `0.4-architecture` 分支；
- 本机可先在 `0.4/` 目录做架构骨架，合并前必须走 git 分支；
- 0.3.0 的 `dist/`、签名制品不再改动。

## 4. 阶段计划

### Phase 0：冻结与基线（本阶段）

- 0.3.0 freeze 备份；
- 记录基线：760 文件 / 91,016 行；单测 1025；Edge/Chrome 212；
- 建 `0.4/` 架构骨架与迁移清单；
- 不改 0.3.0 行为。

### Phase 1：VOM 引擎（目标 +6,000–8,000 行）

- 独立 `0.4/packages/vom`（当前为 ESM + JSDoc 类型，后续可切 TS）；
- 已落：`types/layers/tokens/render/index` 骨架，3 条单测；
- 下一步：六阶段漏斗、affordance 类型化、stable refs、完整 token budget；
- 验收：VOM 输出与 0.3.0 对比夹具一致；新增单测 ≥150。

### Phase 2：动作事务/输入引擎（目标 +5,000–7,000 行）

- 已启动 `0.4/packages/actions`：IntentWAL（追加式、重启 stale、同 tab 拦截）、
  事务状态 prepared→dispatched→committed/unknown、effectState 归一；
- 当前 7 文件 / 约 400 行，3 条单测；
- 下一步：pointer/file transaction、input clock、3 步 fill、virtual row guard；
- 验收：真实 E2E 23i/35d/20q 全绿 + 故障注入。

### Phase 3：协作/捕获引擎（目标 +5,000–7,000 行）

- 已启动 `0.4/packages/collaboration`：authority（open/exclusive/claim/release/handoff）、
  frameState 计数器、capture 引用计数；
- 下一步：passthrough token、2 rAF ack、toolbar/controller；
- 验收：23h/20q 全绿，长截图/视频恢复全绿。

### Phase 4：DSH 插件深度（目标 +10,000–15,000 行）

- 已启动 `0.4/packages/dsh-plugin`：类型化工具定义、唯一名注册表、必填参数校验；
- 当前 5 个核心工具（status/observe/act/plan/ledger），3 条单测；
- 下一步：router/runner/journal/recipe 拆分与执行策略；
- 验收：工具契约、plan/recipe/ledger 恢复、DSH selftest。

### Phase 5：协议/多平台（目标 +20,000–30,000 行）

- 已启动 `0.4/packages/protocol`：单一 method descriptor、owner/effect、feature、
  catalog 重复/分组/feature 汇总；
- 已迁移 0.3 的 165 canonical 方法（methods-legacy，生成器 scripts/gen-legacy.mjs）；下一步 schema/TS codec/执行策略生成；
- 验收：协议方法全量、schema 审计、旧端兼容矩阵。

### Phase 6：测试语料与 4x 收口（目标 +40,000–60,000 行）

- 57+ eval case 组织、fake adapter、tri-state oracle；
- 真实浏览器矩阵；
- 规模门禁：≥250k 为阶段通过，≥300k 为 4x 收口。

## 5. 阶段门禁

每个 Phase 必须同时满足：

1. 新模块单测 ≥ 目标行数的 30%；
2. 真实 Edge/Chrome E2E 212 不回归；
3. schema/协议/scale/source/encoding/preflight 全 PASS；
4. 与 0.3.0 行为夹具对比，无未解释差异；
5. 不修改 0.3.0 发布制品。

## 6. 风险

| 风险 | 处理 |
| --- | --- |
| 4x 变成灌水 | 以真实模块/测试为准，行数只是结果指标 |
| Node 性能不及 Rust | 先行为对齐；关键路径用 CDP/worker 优化 |
| page-lib 单文件注入 | 0.4 评估 MV3 多文件注入与构建链 |
| 外部 Linux/macOS/fsync 不可用 | 明确列为外部项，不宣称已验证 |
| 与 0.3.0 分叉漂移 | 0.3.0 freeze；0.4 每阶段对拍 |

## 7. 本阶段下一步

1. 生成 0.3.0 freeze 备份；
2. 建 `0.4/` 目录骨架与本计划；
3. 进入 Phase 1 VOM 引擎，先落 `packages/vom` 的类型/渲染/层/token 骨架与测试；
4. 0.3.0 不再做低价值小改动。

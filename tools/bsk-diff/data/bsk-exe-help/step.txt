Execute one action, await a known condition, and return synchronized state

Usage: bsk.exe step [OPTIONS] --action <ACTION> --params <PARAMS>

Options:
      --session <SESSION>


      --context <CONTEXT>
          Control context returned by cooperate sync. Required for shared-tab actions

      --scope <SCOPE>


      --depends-on <DEPENDS_ON>
          Legacy strict-policy decision regions. Target policy uses --expect instead

      --policy <POLICY>
          Post-action sync policy. Auto preserves an existing choice or starts target control. Use cooperate sync first when choosing a policy before the action

          [default: auto]
          [possible values: auto, strict, target]

      --observation <OBSERVATION>
          Explicit observation ID for visual or untargeted actions; never inferred from cached state

      --tab-id <TAB_ID>


      --action <ACTION>
          Exactly one ordinary browser action; never retried

          [possible values: click, press, fill, hover, select, drag, scroll-to, wheel, navigate]

      --expect <EXPECT>
          JSON array of target facts to check before input: [{"target":"@e1","field":"text","equals":"Save"}]

      --json
          Emit machine-readable JSON output (when meaningful)

      --params <PARAMS>
          JSON object using the action's protocol fields (ref/selector/value/key/etc.). Session, tab, context and dependencies come from CLI flags, not this object

      --quiet
          Suppress informational output

      --until-visible <UNTIL_VISIBLE>
          Known main-document CSS selector that should become visible after the action. Use a positive readiness signal; visibility alone does not prove business success

  -v, --verbose...
          Increase log verbosity (`-v` debug, `-vv` trace)

      --wait-timeout-ms <WAIT_TIMEOUT_MS>
          Readiness budget in milliseconds, independent of the action timeout

          [default: 5000]

      --save-full <SAVE_FULL>
          Save the unfiltered combined result, atomically, without overwriting

      --baseline <BASELINE>
          Exact saved predecessor for an unchanged post-action sync

      --match-text <MATCH_TEXT>
          Fold only plain numbered fallback buttons outside literal-match windows (repeatable).

          Only stateless `button "item N"` lines may be omitted. Keeps business text, named/stateful controls and complete forms/dialogs. Use `bsk view <saved.json> --find <text>` for text search. A requested full reply is saved before folding.

      --context-lines <CONTEXT_LINES>
          Keep numbered fallback buttons within this many lines before/after each match

          [default: 12]

  -h, --help
          Print help (see a summary with '-h')

Execute arbitrary JavaScript (strict observation required). For passive DOM data use read/extract

Usage: bsk.exe evaluate [OPTIONS] <EXPRESSION>

Arguments:
  <EXPRESSION>  JavaScript expression to evaluate. Wrap with quotes; statements that need an explicit return should `return` from an IIFE or place the value last (CDP returns the expression's value, not a statement's)

Options:
      --session <SESSION>
          Session id (omit to resolve via caller scope)
      --context <CONTEXT>
          Control context returned by cooperate sync. Required for shared-tab actions
      --scope <SCOPE>
          Explicit caller scope name for multi-agent isolation
      --depends-on <DEPENDS_ON>
          Legacy strict-policy decision regions. Target policy uses --expect instead
      --tab-id <TAB_ID>
          Target tab. Defaults to the Agent Window's active tab
      --await-promise <AWAIT_PROMISE>
          Await the expression's resolved value when it returns a Promise (CDP `awaitPromise`). Defaults to true [default: true] [possible values: true, false]
      --observation <OBSERVATION>
          Explicit observation ID for visual or untargeted actions; never inferred from cached state
      --expect <EXPECT>
          JSON array of target facts to check before input: [{"target":"@e1","field":"text","equals":"Save"}]
      --return-by-value <RETURN_BY_VALUE>
          Ask CDP to serialise the result by value. Defaults to true so the CLI receives a plain JSON value instead of a RemoteObject id [default: true] [possible values: true, false]
      --json
          Emit machine-readable JSON output (when meaningful)
      --timeout <TIMEOUT>
          Hard timeout (default 30s). Accepts `30s`, `1m`, `1500ms` [default: 30s]
      --quiet
          Suppress informational output
      --unverified
          Run without comparing the page with any observation: no --observation is needed and nothing is refused because the page changed. Control, the document and tab ownership are still checked. Last resort: first state what the script relies on with --expect and no --observation (target policy) or --depends-on (strict policy), which keeps a real check and also runs on pages that keep changing. The script should check its own preconditions and throw; the result carries `verified: false`
  -v, --verbose...
          Increase log verbosity (`-v` debug, `-vv` trace)
  -h, --help
          Print help

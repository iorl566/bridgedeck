Opt-in website debugging: requests, page context, and recording export

Usage: bsk.exe debug [OPTIONS] <ACTION> [ID]

Arguments:
  <ACTION>  Capture/inspect evidence, manage request rules, or replay a recorded request [possible values: performance, aggregate, duplicates, capabilities, activity, wait, pin, unpin, start, stop, status, requests, request, operations, operation, console, pages, export, rules, rule_add, rule_enable, rule_disable, rule_remove, replay]
  [ID]      Request, operation or rule ID returned by an earlier debug action

Options:
      --session <SESSION>
      --context <CONTEXT>              Control context returned by cooperate sync. Required for shared-tab actions
      --tab-id <TAB_ID>
      --depends-on <DEPENDS_ON>        Legacy strict-policy decision regions. Target policy uses --expect instead
      --run-id <RUN_ID>
      --name <NAME>                    A short task name shown in the extension
      --observation <OBSERVATION>      Explicit observation ID for visual or untargeted actions; never inferred from cached state
      --expect <EXPECT>                JSON array of target facts to check before input: [{"target":"@e1","field":"text","equals":"Save"}]
      --since <SINCE>                  Incremental cursor; records may reappear when their evidence changes
      --json                           Emit machine-readable JSON output (when meaningful)
      --limit <LIMIT>                  List size: 1..100, default 30. Follow next_since or next_offset
      --part <PART>                    [possible values: metadata, request, response, headers, timing]
      --quiet                          Suppress informational output
      --offset <OFFSET>                Body character or pages/console/performance/analysis entry offset: 0..65536
  -v, --verbose...                     Increase log verbosity (`-v` debug, `-vv` trace)
      --max-chars <MAX_CHARS>          Body slice: 1..16384 characters, default 4096
      --pointer <POINTER>              RFC 6901 JSON pointer applied to the selected complete, redacted body
      --rule <RULE>                    Rule definition as JSON. Rules default to one match in the current capture
      --rule-file <RULE_FILE>
      --replay <REPLAY>                Replay JSON with a unique key; reusing the key never sends twice
      --replay-file <REPLAY_FILE>
      --budget <BUDGET>                Output budget: 4096..262144 UTF-8 JSON bytes, default 65536. Export is exempt
      --slow-ms <SLOW_MS>              Aggregate only: slow-request threshold in ms, 0..60000; default 1000
      --window-ms <WINDOW_MS>          Duplicates only: fixed burst window in ms, 100..10000; default 1000
      --include-controlled             Analysis only: include requests affected by rules or agent replay
      --url <URL>                      Requests/analysis: URL substring (case-sensitive)
      --method <METHOD>
      --resource-type <RESOURCE_TYPE>
      --status <STATUS>
      --state <STATE>                  [possible values: pending, complete, failed, redirected, interrupted]
      --kind <KIND>                    [possible values: all, business, resource, extension]
      --fields <FIELDS>                Comma-separated optional request fields. Identity and body availability remain
      --wait-ms <WAIT_MS>              Wait for the running command: 0..60000 ms, default 10000; does not resend it
      --command-id <COMMAND_ID>        Wait until this command is no longer running; otherwise wait until the session is idle
      --output <OUTPUT>                Export JSON to a new file, returning only its path and size to the agent
  -h, --help                           Print help

Run several decided actions in order, stop at the first failure, and return synchronized state

Usage: bsk.exe plan [OPTIONS] --steps <STEPS>

Options:
      --session <SESSION>

      --context <CONTEXT>
          Control context returned by cooperate sync. Required for shared-tab actions
      --scope <SCOPE>

      --depends-on <DEPENDS_ON>
          Legacy strict-policy decision regions. Target policy uses --expect instead
      --tab-id <TAB_ID>

      --observation <OBSERVATION>
          Explicit observation ID for visual or untargeted actions; never inferred from cached state
      --steps <STEPS>
          JSON array of 1-20 steps. Each is an object with `action` (click, fill, select, press, hover, scroll-to, wheel, drag or wait-for-element), that action's protocol fields (ref/selector/value/values/key/etc.) and optional `expect`
      --expect <EXPECT>
          JSON array of target facts to check before input: [{"target":"@e1","field":"text","equals":"Save"}]
      --until-visible <UNTIL_VISIBLE>
          Known main-document CSS selector that should become visible after the last step
      --json
          Emit machine-readable JSON output (when meaningful)
      --wait-timeout-ms <WAIT_TIMEOUT_MS>
          Readiness budget in milliseconds, independent of the steps' timeouts [default: 5000]
      --quiet
          Suppress informational output
      --save-full <SAVE_FULL>
          Save the unfiltered combined result, atomically, without overwriting
      --baseline <BASELINE>
          Exact saved predecessor for an unchanged post-plan sync
  -v, --verbose...
          Increase log verbosity (`-v` debug, `-vv` trace)
      --match-text <MATCH_TEXT>
          Fold only plain numbered fallback buttons outside literal-match windows (repeatable)
      --context-lines <CONTEXT_LINES>
          Keep numbered fallback buttons within this many lines before/after each match [default: 12]
  -h, --help
          Print help

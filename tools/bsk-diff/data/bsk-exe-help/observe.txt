Produce a semantic VOM observation with perception probes

Usage: bsk.exe observe [OPTIONS]

Options:
      --cursor <CURSOR>            Continue the same observation. Use current refs before continuing
      --context <CONTEXT>          Control context returned by cooperate sync. Required for shared-tab actions
      --session <SESSION>          Session id (omit to resolve via caller scope)
      --depends-on <DEPENDS_ON>    Legacy strict-policy decision regions. Target policy uses --expect instead
      --scope <SCOPE>              Explicit caller scope name for multi-agent isolation
      --observation <OBSERVATION>  Explicit observation ID for visual or untargeted actions; never inferred from cached state
      --tab-id <TAB_ID>            Target tab. Defaults to the Agent Window's active tab
      --expect <EXPECT>            JSON array of target facts to check before input: [{"target":"@e1","field":"text","equals":"Save"}]
      --max-depth <MAX_DEPTH>      Cap on VOM tree depth before truncating
      --json                       Emit machine-readable JSON output (when meaningful)
      --max-tokens <MAX_TOKENS>    Soft cap on rendered tokens (estimated; CJK-aware)
      --debug-surfaces             Include conditional surface probe diagnostics in JSON output
      --quiet                      Suppress informational output
      --probe-hover                Actively hover page controls to reveal hover-only menus and tooltips. Costs seconds of wall clock and touches the live page, so it is off unless a static observation looks like it is missing hover content
  -v, --verbose...                 Increase log verbosity (`-v` debug, `-vv` trace)
  -h, --help                       Print help

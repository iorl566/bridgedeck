Wait until an element becomes visible / hidden / attached / detached

Usage: bsk.exe wait-for-element [OPTIONS] [TARGET]

Arguments:
  [TARGET]  Snapshot/observe ref (`@e3`, `e3`) or CSS selector

Options:
      --ref <REF>
      --context <CONTEXT>          Control context returned by cooperate sync. Required for shared-tab actions
      --selector <SELECTOR>
      --depends-on <DEPENDS_ON>    Legacy strict-policy decision regions. Target policy uses --expect instead
      --state <STATE>              State to wait for: `visible`, `hidden`, `attached`, `detached`. `hidden` means absent or not visible; `detached` requires absence [default: visible] [possible values: visible, hidden, attached, detached]
      --observation <OBSERVATION>  Explicit observation ID for visual or untargeted actions; never inferred from cached state
      --timeout <TIMEOUT>          Inspection budget (default 10s, max 5m). Timeout returns satisfied=false, exit 0 [default: 10s]
      --expect <EXPECT>            JSON array of target facts to check before input: [{"target":"@e1","field":"text","equals":"Save"}]
      --poll-ms <POLL_MS>          Poll interval (16..=2000ms, default 100ms); shortened near the deadline [default: 100]
      --json                       Emit machine-readable JSON output (when meaningful)
      --session <SESSION>
      --quiet                      Suppress informational output
      --scope <SCOPE>
      --tab-id <TAB_ID>            Target tab. Defaults to the Agent Window's active tab
  -v, --verbose...                 Increase log verbosity (`-v` debug, `-vv` trace)
  -h, --help                       Print help
